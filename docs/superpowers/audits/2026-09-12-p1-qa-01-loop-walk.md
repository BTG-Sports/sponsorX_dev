## Gaps found → fixed in this audit

All three were the same defect class: an unwired control rendered as live with
no explanation, on athlete surfaces (admin surfaces were already meticulously
annotated):

1. `/athlete/invitations` — **Decline** button: no tooltip. Fixed: annotated
   as a wireable transition not wired in the fixture build.
2. `/athlete` dashboard — **Decline** button on invite cards: same fix.
3. `/athlete` dashboard — **Upload proof**: tooltip existed only for the
   minor/guardian case; the default case was silent. Fixed: annotated with the
   direct-to-R2 presigned upload destination (guide §11).

## Observations logged, not filed as tasks

- **Sponsors have no brief-status surface.** After "Add to brief" (step 4) the
  sponsor's next visibility is the report (step 11); matching progress is
  BTG-internal. This matches the §13 managed model — BTG staff drive matching
  and contact the sponsor — so it is treated as by-design for Phase 1, not a
  gap. If the lead disagrees, it is a *plan* change (new task in the Phase 1
  markdown by PR), not a tracker edit.
- Steps 4→5 (brief → matching) and 9's reward *creation* are staff-mediated by
  design; the fixture build represents them on admin screens.

## Method note

Marker-based fetch of every screen on the dev server plus manual read of each
loop CTA's annotation state. Fixes verified by `tsc`/`eslint` and re-render.
